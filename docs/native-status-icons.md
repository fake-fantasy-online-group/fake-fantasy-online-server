# 原状态图标完整审计与修复（2026-10-12）

## 原始证据与结论

原资源包 `res_ff21.pkg` 的 `zipbin/ov_res.bin` 明确声明 `ResExceptDesc.SmallMap`，它是每个状态**每个等级**的原图标资源号。`zipbin/ov_exceptdesc.bin` 里保留了该字段；旧 SQL 导入只展开了 Desc/Name，丢掉了 SmallMap。此前只审计 JSON/技能图标不能证明原状态没有图标。

- 原 `ov_res.bin` SHA-256：`c232005d56717e2e255e1e927dde709b243e34b7599e00c45d67f0760c5e270f`
- 原 `ov_exceptdesc.bin` SHA-256：`caccc5a2f58687240d811458d895499a2dddf2ddeed10d5f383a928117bb3119`
- 原结构：16 字节表头，206 物理行，每行 12324 字节。行首 Type 为 u32，随后 40×308 字节等级记录；每级 Desc[256]、Name[32]、SmallMap u32（级内偏移 288）。
- `ov_res.bin` 字段名 SmallMap 在字节 242600；前 88 字节描述符给出 size=4、offset=288、count=1、stride=4。levels 在字节245120，描述符给出 offset=4、count=40、stride=308。
- 206 物理行包含 3 个 Type=0 占位行，实际为 **203 个正状态 ID**。其中 **191 个状态至少一个等级有正图标，12 个状态全级为原0**。不能把原0或空白占位凭猜测填图。
- 24 个状态随等级换图，必须按状态号+等级查表。不能只设一个状态级常量。
- 共 140 个不同正图标，全部在原包存在并经生产 DimgDecoder 成功解码到非透明像素；其中10203、10205本身就是极简色块，未替换。

中毒1001原图=5030；使毒1018原图=7037。技能10211的图标5030与“使毒”状态图标不同，这正是不能混用来源技能图的反例。冰冻1004原图7087，也不应继承冰之盾1038的7093。

## 接线与修复

1. `server/migrations/000000_init-57.sql` 恢复 `gamedata.ov_exceptdesc.level_small_maps` 的40个原值，row_no+type双重匹配，必须更新206行。
2. `LoadStatuses` 按1基等级读取 SmallMap；`IconKnown` 明确区分原0与缺少原表的项目新增状态。原值包括0均不可被技能、道具、反击来源替换。
3. `visibleStatuses` 以当前原表精确状态+等级纠正旧角色存档里的来源图标，仅改变发送时展示，不修改保存的数值、持续时间或伤害。

## 旧库部署

`cmd/migrate` 只初始化空库，不会自动升级已有库。先停止旧server，在正确游戏数据库执行以下幂等增量，再启动新server；只变静态图标元数据，不变角色/道具记录。

```sh
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -1 -f server/migrations/000000_init-57.sql
```

只执行本片段，**不要重建数据库，也不要重跑全部init**。row_no/type不匹配时整事务失败，先检查原数据版本。空库正常init会自动包含本片段。仅替换客户端或server二进制而未执行此SQL不算完成部署。

核验：

```sql
SELECT type, level_small_maps[1] AS level1_icon,
       level_small_maps[2] AS level2_icon
FROM gamedata.ov_exceptdesc
WHERE type IN (1001,1018,1004,1176);
```

预期1001=5030、1018=7037、1004=7087；1176/1=4419，1176/2=0。
