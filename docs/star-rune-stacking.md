# 星篆堆叠：数据与发布约束

- 范围仅 1900028001–1900028028 共 28 种星篆，单格沿用上限 999。
- 仅物品 ID、完整 Card 快照、绑定、锁定及其他实例字段一致的星篆可合堆；UID 和数量不参与等价比较。普通卡、装备仍单件实例。
- UID 标识一份同质堆。全堆移动保留 UID，部分拆分/转移/镶嵌为移出的部分生成新 UID；消耗只减数量。镶嵌一次一枚，不改原属性。
- migration 113 开启配置堆叠，并给 `card_instances` 增加 nullable `snapshot_bound` / `snapshot_locked`。旧 NULL 行继续从根实例保护标志恢复；仅星篆读取新快照标志。迁移不改人物库存，也不自动合并现存单枚。
- 数量继续存于各位置表；实例事实保存共享属性。重登时必须保留位置数量，不能按旧逻辑重设为 1。
- 客户端 JSON 字段、opcode 不变；数量沿用原生背包/仓库消息。旧客户端已有拆分和按格单枚镶嵌交互。

## 发布与回滚

先应用 113，再运行本版本服务端。迁移本身可重复执行，缺失定义时整批失败。

**一旦新版本已保存多枚星篆堆，不能直接回滚旧服务端继续运行。** 旧服务端的实例恢复逻辑会把位置数量重设为 1。回滚须先停写，再通过经验证的拆堆迁移（每枚独立 UID、保存完整属性）或一致的部署前备份恢复；不能只撤销 `can_pile`。本变更没有自动执行上述回滚或修改任何真实角色库存。

## 回归覆盖

领域测试覆盖等价/非等价合并、容量、拾取余量、奖励、拖动、拆分、镶嵌取回、单枚周天鼎消耗、制作预览满包合堆且不分配永久 UID。
场景测试覆盖原生连续镶嵌、拆分、仓库转移、交易、邮件失败回滚及保护状态同步。持久化测试覆盖数量与完整快照往返，并拒绝非星篆多枚实例。发布前仍应运行集成分支完整测试。
