# 周天鼎批量装备分解（服务端）

- 沿用 35 格 CubeInputs，玩家投入哪些装备就分解哪些，不扫描背包；旧版客户端无需新协议/功能开关。
- 两件及以上、仅装备投料进入批量分解。翅膀 + 暗金的旧提取配方已撤销，任何包含翅膀的组合均不回退分解。单件分解保持原流程。
- 每件按自身等级、品质与部位结算原矿；同矿聚合，符合旧规则的镶嵌卡片返还；普通与暗金可混投。
- 继承旧数量语义：请求 Count 是展示提示，装备实例实际 Count 必须为 1；重复/非规范 UID、重复背包实例、非本人/错页签/锁定/损坏镶嵌数据均拒绝。
- 先对原始背包逐件验证、释放全部目标格、检查全部随机结果的保守容量上界，再随机结算。只构造候选背包，不提前修改角色。容量仍按各物品原页签计算；腾出的装备格不等于材料格。
- 预览沿用旧 Materials 列逐件显示消耗；原协议没有随机产物列表。不能以预览确定随机矿种，避免重试预览挑结果。
- 混合分解的计划沿用 life.salvage.unique 标识，因此现有 ConsumedUIDs 威能记录循环、首次任务、背包、状态和回执同一原子提交。纯普通装备沿用 life.salvage.normal。
- 原有候选缓存、版本检查和回执重放保证失败/双击/丢 ACK 不重复扣装备或重新抽产物。
- 未改迁移、数据库、客户端或线上部署。补丁只改 domain 规划及 matcher，可单独移植到 life-only 分支；新增 scene 测试依赖 combined codex 基线。
