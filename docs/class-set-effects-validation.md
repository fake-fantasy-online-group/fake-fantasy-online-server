# 五职业套装效果：实现与验收边界

## 门槛和数据库

使用原有五套，不增加第二套：夜色拥抱(1)、信仰之翼(2)、哲理之石(3)、胜利王座(4)、勇气之刃(5)。新门槛为原2→2、原6→4、原8→6、原4→8。新技能效果分别在4/6件激活。计数沿用可用、未破损装备及套装部件分组，职业必须匹配。

迁移93只克隆五套需要放大的10张属性卡到专用ID，并调整五套引用，不修改共享原卡，不添加覆盖表。2件HP/MP为2500；4件原攻击奖励分别为刺客240、药师200魔攻、术士250魔攻、剑客480最大物攻、战士540最大物攻。原暴击奖励在6件，原命中/魔防奖励在8件。

数据库测试通过真实PostgreSQL独立实例验证：原始数据执行迁移、重复执行、目标值、原卡及其他套装无变化、缺失引用和专用ID冲突拒绝。生产库未操作。

## 已实现的规则

- 战士4：当前缺血比例作为独立增伤乘区；6：最终最大生命×2、面板物攻×1.6、移速×1.2，受伤×1.5、当前生命10%替代技能法力费、20%吸血。
- 剑客4：挑衅实际释放增加不羁，30秒、最多10层，每层5个百分点，10层合计50%，整项作为独立减伤乘区；6：旋风剑实际释放消耗一层，本次全部目标伤害翻倍。
- 刺客4：淬毒术的固定总毒伤增加面板物攻均值×10，按原节奏分摊；6：再次成功施加淬毒前按原淬毒尚可发生的剩余伤害20%附加伤害，不扣除毒余额，不改变原覆盖规则，也识别其他刺客的同种淬毒。
- 术士4：冰火施法相互给予另一系50%伤害、3秒、刷新不叠加；6：每个命中目标追加一次已学等级的火弹术或冰箭术。
- 药师4：对友军每次名义治疗额外复制给自己，自己治疗自己不重复；每3秒回复3%最大法力。6：伤害技能追加治愈术，治疗技能追加光弹术；单体以目标为中心200范围，群体沿原几何范围。成功施加回春也算一次治疗施放，持续恢复tick不重复触发6件。

追加法术使用相应技能当前已学等级及原效果，未学习不凭空赋予；免费、无额外冷却，不递归触发套装。套装增伤和减伤不被旧装备100%增伤或45%减伤上限吞掉。

## 明确采用但未经用户逐条指定的工程口径

- 战士生命翻倍指最大生命；穿脱沿用原系统当前生命上限差量处理，不另补百分比生命。
- 血费向下取整，生命大于1至少扣1，生命为1扣0以免资源扣费自杀；费用不走伤害、受伤加成或吸血。
- 吸血按原战斗事件DamageDealt.Amount计算，沿用原系统过量击杀伤害口径；不触发额外攻击。
- 不羁刷新整组30秒，不单独记录各层倒计时；合法释放但无目标的挑衅也叠层。
- 多个友军分别被治疗时各复制一次名义治疗，额外套装治疗不会再复制或触发伤害。
- 临时冰火增伤、不羁和回蓝计时不跨死亡、卸装或退出场景保留；重登后穿戴仍激活常驻效果，毒伤快照沿原状态保存/恢复机制。

## 云端验证方法

从server目录执行：

```sh
go test ./... -count=1
```

定向测试为TestClassSet及TestCasterSets，包含实际施法/攻击、多目标去重、费用、满血溢出治疗、穿脱及破损、失效清理、真实导入技能定义、等级和追加技能时长、毒刷新/延迟调度/快照保存。数据库测试使用tests/sql/validate_class_set_upgrade.py，需要原生PostgreSQL工具路径和新的空工作目录。

服务端物品描述已包含新门槛、数值和技能说明。客户端既有物品描述链路可显示这些文字，不需要为描述重新打包。云端测试不等于客户端实机视觉验收。
