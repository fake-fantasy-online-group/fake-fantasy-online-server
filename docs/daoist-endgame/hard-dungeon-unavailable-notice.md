# 困难副本入口不可用提示

2026-10-13。此变更只是可用性提示修复，**没有恢复、开放或实现困难副本**。

## 行为

参考客户端已有的七条精确命令现在通过现有原生 `0x8008` 文本动作（`displayMode=1`）提示“困难模式暂不可用”：

- `taoyu hard`
- `dungeonhard 20100`
- `dungeonhard 20300`
- `dungeonhard 20600`
- `dungeonhard 20701`
- `dungeonhard 20801`
- `dungeonhard 20901`

入口仍是原 `0x1006 Str(command)`；没有新增协议或修改客户端菜单。该白名单在既有长度校验后、GM权限分支前处理，只向已进入游戏、账号与角色存在、角色/实体/场景身份有效且不在等待地图确认的会话发送提示。普通玩家收到同一提示，无须GM权限；真正GM命令仍执行原权限检查。

只匹配客户端原字面值，不扩展大小写、空白、斜杠、`gm` 前缀、未知地图或额外参数。提示路径不向场景投递命令，不创建副本、不修改角色/队伍/库存/金币，不授予任何入场权限。它不验证或声称NPC授权成功，因为没有执行入场。

普通 `taoyu` 未接入此路径；map507的 `Trap20502` 继续使用既有普通塔狱服务端门。此修复不会添加第二次传送。

## 规则边界

参考客户端的困难菜单和塔狱“头目血量最高约24倍”只能证明前端有相应入口与描述，不能推出逐怪属性、经验、掉落、限时或实例共享规则。现有原SQL和重建服务端没有对应完整规则；原SQL“目前只开放普通”及 `ov_pworlddefend.difficult` 属于天神大考验，不适用于这七个副本。未经配套来源验证，不推定原参考服实际开放状态，不猜测倍率。

## 验证

在 `server` 目录运行：

```sh
go test ./internal/session -run '^TestNativeHardDungeonUnavailable' -count=1
```

独立测试覆盖七条合法命令的真实 `OnPacket(0x1006)` 解码及唯一原生提示字节，普通账号仍不能执行GM命令，未登录/选角/关闭/转图/缺失身份时无提示或操作，普通 `taoyu` 与非精确输入保持原路由。真实场景Actor测试另核对金币和背包不变、不创建实例、不产生 `0x803a` 传送。

这不是困难入场、困难战斗或客户端视觉验收；困难模式仍不可用。
