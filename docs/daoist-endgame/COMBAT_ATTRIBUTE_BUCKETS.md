# 战斗属性桶与来源边界

日期：2026-10-13。范围：本次云端源码重构，不代表线上部署或实际客户端游玩验收。

## 审计结论

原实现并非“每件装备各写一套伤害公式”。原始提交 `b99d03f` 已有 `Compute/applyAffix`、`combat.Strike` 与场景状态结算；本轮以前的装备触发伤害也调用同一个 `CalculateStrike → resolveStrikeStatuses`。新普通数值沿用原属性管线，元素和条件修正沿用已有有类型的通道。

初次审计确认的具体例外：

1. 在线周期回血只按 `LastAstralRune` 物品号识别，不能由其他同机制来源复用。
2. 原生装备说明将所有合并后的 attr38 都写成“每2秒恢复”，把普通生命恢复与周期回血错误合并成同一个意义。
3. 光环 RefreshMS 字段曾被固定500ms扫描覆盖；现每个来源使用自己的刷新与租约节拍，离队、死亡、下线或换来源即失效。
4. 补击 PvP 缩放整数结果为0时，曾与“未配置缩放”混淆并回到全额伤害；现显式标记配置存在，零值按既有最低伤害规则结算为1点。未设置仍保留原伤害，现有正常补击系数不变。配置0不是禁用标志；禁用应移除该效果或使用受支持的触发关闭配置。

五种装备技能形态原先按形态 ID 选闭集执行方案，没有按装备 ItemID 另算伤害。有限行为类型的代码是必要的，但范围、倍率、间隔、触发技能等内容参数不应固定在这些分支。现改成数据库形态规则选择有限 Behavior，参数进入原有技能几何、伤害比例、陷阱和 Restore 接口。形态 ID 只用于查配置、来源绑定、去重和展示，不再决定数值公式。

## 保留原有属性计算

`domain.Compute` 仍是原始数值属性入口：

1. 角色六维与装备固定六维相加，再应用装备/被动的同桶六维百分比。
2. 由六维推导二级属性，再加装备白字及固定词条；同桶二级百分比相加后应用一次。
3. 状态固定值、状态百分比分开累积，状态百分比以装备完成后的基线计算，避免逐个 buff 复利。
4. 本件局部强化先折成该件基底的绝对增量，不乘其他装备、卡、精炼或人物整张面板。

`CombatDamageBuckets` 不再计算一次 Stats。它承接原攻击/防御公式之后的修正。来源先完成有效穿戴、快照、触发条件、队伍/范围等判断，然后贡献普通数字。算术阶段不查询装备、技能形态或物品名称。

## 一次直接伤害的明确顺序

以下是原有数学规则的集中表达，本次不改原技能基准或静默重平衡：

1. 原生命中、技能倍率、物理固定抗性/魔防及魔法固定抗性、暴击由 `CalculateStrike` 计算。物理防御是命中对抗，不擅自改成物理减伤。
2. 已有技能平伤、来源快照的状态平伤及宠物附加按原先规则处理。
3. 已满足条件的增伤与匹配元素增伤进入加算桶。原装备元素增伤在 PvP 内折半一次，光环使用自己的配置效率；所有带效率的贡献保留精度直到共桶求和后才截断，默认50%与原结果一致。当前合计 +100% 上限保留，这是既有、待进一步审核的数值规则，不是属性桶架构必然要求。
4. 固定技能补击的 payload 缩放单独应用。
5. 承伤增加同桶相加，作为一个承伤放大层。
6. 元素抗性先减穿抗，再钳制到 -50%～75%；穿抗上限保持 PvE 30%、PvP 折半后15%。负抗性是放大，放大后的值作为减伤基线。
7. 装备/条件/光环的同语义减伤加算，现有桶上限45%；技能减半层及状态百分比减伤依原顺序作用。状态/宠物固定减伤也计入同一个最终减伤预算。
8. 上述百分比/固定减伤合计不超过这一步基线的75%。该基线在原生攻防公式之后；不能把此说成“原始攻击力最多被任何机制减少75%”。
9. 真正免疫、全额反射、可消耗护盾与元素吸收仍是独立生命周期机制。护盾可以挡掉全额伤害；吸收有既有比例及每秒实际回血预算，致死不复活。
10. 场景只提交一次目标 HP，随后保持原事件、死亡、控制、归属及触发边界。

同名条件特性仍取最强，不因多个同名装备重复叠加；不同已满足条件的特性才加入既定桶。条件求值改变桶输入，不修改全局基础技能表。已受理施法保留原来源快照；持续来源继续使用既定的原值/当前值较低规则。

## 周期恢复桶

周期恢复来源必须显式配置 `RegenerationIntervalMS`，其 attr38 绝对值取持久化卡实例快照。普通装备/卡的 attr38 不因字段相同自动获得在线脉冲。

- 同节拍固定恢复相加；不同节拍分别计时，不互乘、不合成一个虚假的总节拍。
- 合法节拍是世界 TickMS 的整数倍，范围一个世界帧至60秒。这是精度/资源边界，不是平衡公式。
- 原轸保持每2秒恢复其存档值。金额、UID、卡快照、孔位和物品资源均不改写。
- 换装、来源/资格变更、死亡或转场继续清理既有时钟；稳定的无关属性刷新不推迟计时。重新有效后等待完整周期。
- 暂停、离线或跳过多帧不补发历史脉冲；每个到期桶最多结算一次，实际回血由普通 `combat.Restore` 限制为缺失生命，不复活。
- 说明按相同的机制与节拍分桶；普通“生命恢复 +7”和“每2秒恢复3点”分别展示，不写成每2秒恢复10点。

## 有限行为，不是任意脚本

五种形态只开放 `area_fan`、`area_line`、`detonate_owned_trap`、`delayed_heal`、`instant_cast`。配置包含原技能、职业、目标上限及相应有限参数。未知行为、无效几何、越界参数在配置构造时拒绝。

- 范围变化继续使用 `SkillAreaTargeting` 和原目标裁决。
- 比例变化继续使用原精确分数倍率与普通伤害结算。
- 引爆复用自己已支付的陷阱载荷和原/当前较低来源，不生成递归装备触发根。
- 延迟治疗保持来源装备 UID/修订校验、实际缺血预算、死亡/失效取消，并调用普通 Restore。
- 即发改变施法定义副本的吟唱与最低冷却，不免除原法力、不重置冷却债务。

光环刷新、租约、半径与 PvP 效率、补击 PvP 效率均为有限配置。500ms/1000ms/240距离/50%光环PvP和35%补击PvP保留为迁移默认，而非校验器强制等式。光环租约须覆盖刷新周期，节拍须符合世界帧精度，半径与频率有资源上限；这些边界不是单件装备数值。不同来源的时钟彼此不延长租约，移除来源同时删除其时钟。

补击原本刻意不触发下一轮装备补击、吸血及附加控制。本次不把这些递归限制当作遗漏而打开。DOT 和反射的独立直接 HP 路径在原始提交已存在，语义是无普通命中/暴击及无反射递归；本次不借架构重构擅自让它们重吃普通攻击防御或吸血。补击受击耐久与普通攻击的收尾差异已记录，未在没有明确平衡裁定时改变。

## 回归范围

- 数值桶与测试内冻结的重构前算术进行10,000组确定性随机等价比较（oracle不调用生产缩放、减伤或饱和helper），包含 PvP、缩放、溢出饱和、抗性/穿抗、状态放大与减伤预算。
- 场景真实resolveStrikeStatuses覆盖装备/条件特性/实时光环同值增伤，以及装备/条件/状态/光环单层同值减伤（不同层的单独兼容性，不宣称可合并互换）；另验证physical_guard与physical_mitigation光环共用45%加算上限，状态仍为独立乘层。条件关闭和来源移除下一击生效；同桶贡献换顺序不复利；既有 +100% 增伤及75%减伤上限明确覆盖。
- 配置把周期恢复移到另一符文 ID，并改为1500ms：旧 ID 失效，新来源及新节拍生效。
- 1000ms/2000ms 恢复混用，每来源只计一次，无跨节拍复利或离线补发。
- 普通 attr38 与周期 attr38 组合的原生装备说明和实际恢复分别验证。
- 形态重命名、参数变化后仍按同一个有限行为执行，内部行为/参数不泄漏到严格客户端 DTO。
- 两种光环节拍分别刷新，不互相续租；换装备来源、离队、死亡及下线不遗留时钟或收益。补击unset/explicit-zero及极小PvP系数分开覆盖。
- 既有形态等级/快照、范围、延迟治疗、陷阱、冷却、装备失效、元素、补击、光环及生命周期测试仍需在最终合并后的配置状态执行；测试通过状态以运行记录为准。
