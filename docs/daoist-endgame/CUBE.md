# 周天鼎：可执行配方与事务契约

周天鼎将旧器归元、星篆炼制和仙遗成长连成一个实际循环。实现不需要新美术；材料图标由启动流程选用已验证的现有资源。全部结果由服务端生成，客户端和 agent API 仅发送真实器物 UID、材料类型与精确数量、投料顺序，由服务端匹配数据库配方。历史按配方编号寻址的底层协议仅保留兼容。

## 实际入口和材料

完成过一次试炼后，在试炼小仙处接取《问鼎周天》；接取后完整通关一次任意层演劫洞天（本人须有结算资格，不要求限时），到龙城巧匠左慈处领取永久绑定周天鼎。工具放在背包中右击打开现有12格容器，使用不消耗。物品号1900028301和入口身份来自数据库，图标复用原生清神炉9515的9509，不硬编码客户端身份。场景中的鼎NPC已由迁移84移除；原生商会门、室内和出口不变。放入真实背包物品与精确数量后问鼎、确认炼化；不展示操作、配方或成品列表。放入/取回只是客户端选择，取消或断线不会移动物品。穿戴装备须先卸下。每次仅保留一份有效预览，库存变化或选择变化后需重新问鼎。

- 星髓，1900028201：解器归元、仙遗化韵、星篆归尘产生。
- 净煞尘，1900028202：演劫洞天结算产生。周天鼎不凭空制造此材料。
- 八仙余韵，1900028203：仙遗化韵产生。

三种材料均为真实的物品页堆叠物。周天鼎产生的材料和新星篆绑定；分解返还的既有孔内卡保留其保存的 UID、属性、绑定状态；已移除额外单孔取出接口。材料消耗跳过锁定堆叠。

## 指令与预览

配方来自开服时 PostgreSQL 装载的不可变 `CubeRuleTable`。上表为迁移86后的维护配置参考，游戏与 agent API 不展示这个配方目录。

当前 `cube.quote` 带 `expectedRevision`、`cubeInputs`（1–12个 `{uid,count:1}` 或 `{itemId,count}`）。`MatchCubeInputs` 检查精确材料数量、物品形态、既有操作条件，从 DB 规则匹配。

相同投料匹配同操作/同费用的多个变体时，执行阶段等概率选择一个：凝篆为28种既有星篆，转换为同象且不同于来源的有效产物。预览不抽取随机结果，不披露候选配方列表。跨操作或费用歧义直接拒绝。当前62条启用 DB 规则可参与匹配；四条停用规则的旧编号请求和原投料均有拒绝回归测试。

预览只给出冻结 quoteId、revision、费用、当前投料的结果/风险和到期时间。`cube.execute` 仅需 requestId、expectedRevision、quoteId ；服务端重验当前背包持有绑定工具及任务完成资格，非零旧NPC参数一律拒绝。规则或目录快照被替换时，旧预览与已缓存候选一并作废。

历史 recipeId/targetUid 形式的服务端底层兼容路径保留，当前 native UI 与 agent API 不再使用或披露该接口；该路径同样只能访问 enabled 配方，不能绕过停用。

预览有效期60秒。指纹覆盖完整背包每格保存的实例字段、铜币和选定配方/UID顺序；原生移动、精炼、锁定、消耗、镶嵌或钱币变化，即使未增加演劫revision，也会使旧预览失效。

预览不调用游戏随机源，不创建永久UID，也不显示虚构的具体随机结果。灵性与孔数随机项只承诺范围/概率；实际掷值仅在完整预检通过后的执行阶段发生。容量预检先行，所以背包已满的请求不会借失败反复探测随机数。

## 事务与安全边界

`domain.PlanCube`只处理克隆。先做完整无随机预检，再生成执行候选。场景将候选背包和铜币交给核心 `endgameCommit`，同一笔事务包含真实消耗、结果、演劫revision和持久化请求回执。提交确认前，在线背包和铜币不改变。同一预览第一次执行的候选保留至预览失效或成功；确定回滚后的同一预览重试复用该候选，同时重新验证实时条件与背包指纹，不再掷值。失败不发布孔数或其他随机结果；重复成功请求由核心回执查询先行返回，报价过期或消失也不会再次扣费。

每次验证：物品属于自己的背包、槽位与模板一致、实例数量为1、UID正数且在所有背包根/孔位中不重复、材料足够且未锁定、孔位完整且未超容量。提取后容量不足整笔拒绝；允许本次完整消耗材料腾出的格子容纳产物。不存在配方可复制符钥。

### 真实取得循环

普通可染色掉落 → 分解得星髓；试炼符钥 → 演劫洞天 → 净煞尘、星篆与装备；三类来源即可开窍、凝篆或唤醒仙遗。唤醒还需分解现有仙遗取得4枚余韵；仙遗每件产1枚余韵，重铸亦需4枚。现有8种操作由这些实际来源和62条启用服务端配方到达。

## 双开孔路径与原配方审计（2026-10-11）

原生入口由 `scene/socket.go` 与 `gamedata.ov_enchase` 驱动，不调用周天鼎1006，原材料、金额、技能、保护、失败/损毁率以及每次成功仅增一孔的行为均未改动。原始91条配方的成功率为20%、30%、40%、50%、60%、80%，并非100%保证：例如row45为10火铜(4006)+1000铜币、80%成功；row0为45太极碎片(36167)+55东皇钟(36169)+350000铜币、30%成功。不能把“原配方”描述为保证成功。

迁移86后的1006只消耗4星髓，铜币费用为0，不再要求洞天净煞尘。一个可分解普通基底产出8+floor(等级/5)星髓，至少足够两次开窍；一枚星篆归尘产出4星髓，足够一次。材料获取因此可走已有普通装备/星篆回收，不必凑原生特定矿石或洞天材料；原生配方的材料、费用和成功率仍不改动。实际掉落时间/市场价格未测。

仅无孔装备可执行。范围依据该实例天生词条留下的属性容量计算，1至5的所有容量均有边界测试。开过后即使取出全部星篆仍保留孔数，因此不能免费洗孔或用本配方重置。低孔结果仍可按适用的原生逐孔配方继续养成。全满装备背包也能原地修改，不创造额外装备实例。

成功响应在现有`result`字典附加`socketCount`并在完成文字报告孔数；没有新增协议结构或数据库迁移。预览只显示范围、等概率与成本。进程重启前若事务未提交，任何候选结果都没有向玩家公开；重启后不能利用未见结果择优。若事务已提交，持久回执及背包结果共同恢复，重复requestId直接回放，不会重收费/重掷。
