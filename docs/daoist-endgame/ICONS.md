## 选图依据

2026-10-11 对既有 `res_q21_001.pkg` 的物品小图以及 `res_05diff.pkg` 覆盖图进行了像素解码与联系表目视检查。只读取了相关索引和物品图标数据段，没有下载整个资源归档，也没有把图片、GSO、PKG 或联系表加入源码仓库。

32 个新增物品使用 32 个不同的小图；在 q21 与「05diff 优先、q21 补齐」两种资源顺序下均无重复像素。四象分别采用卷符、符纹、圆印、枝状符纹作为主要轮廓；按宿名的木、金、土、日、月、火、水选择绿色、金色、土石色、日轮/星芒、月牙、红焰、水蓝意象。既有图案是符篆意象，不冒称逐一画出了二十八种宿兽。

## 加载与缺失处理

服务端 `cmd/gameserver/endgame_icons.go` 使用图像编号而非原物品编号，注册时通过现有物品图标覆盖协议发送。选择不再依赖数据库第一条物品或第一张卡的任意图标。背包、tooltip 与周天鼎均沿用 `NetClient.LoadItemIcon` 的同一映射；不引入另一套 tooltip 图标绘制。

客户端若找不到服务端指定图像，使用最多两个直接 sprite 路径尝试同义的备用小图/大图。星篆按七种元素保留七个备用图案；符钥、三种材料各有单独备用图案。不会把 32 项退回同一通用图。仍缺失时保留原有空图行为，并对每种新增物品最多记录一次诊断；资源缺失不阻止服务器启动，也不导致递归加载。

备用编号按木、金、土、日、月、火、水为 `3608,3573,4312,4094,4024,3607,3606`；符钥为 `3303`，材料为 `3559,4019,3619`。备用图也检查了上述两种包顺序下的实际像素。

## 可复验边界

`icon-assets.json` 仅保存图像编号、相对路径、尺寸和校验值，不含素材字节。40 个独立素材覆盖 32 个主图和 11 个语义备用图（3 个备用图复用主图）。按两种资源顺序分别检查，共 80 个解析结果。

对有权使用的包自行提取上述小图到外置目录后运行：

```
python docs/daoist-endgame/validate_icons.py --mode q21 --resource-root /path/to/q21-extracted
python docs/daoist-endgame/validate_icons.py --mode classic --resource-root /path/to/classic-resolved
```

缺失文件或与审阅版本不同的文件会明确失败；校验不以「编号出现在表里」代替素材存在。工具同时验证源码映射与审阅清单一致，以及各组的差异性。不同合法资源版本若哈希变化，应重新目视审阅后更新清单，不能盲目放宽校验。

服务端聚焦测试：`go test ./cmd/gameserver -run 'Test(RegisterEndgame|EndgameIcon)'`。
客户端在 Unity 外执行实际 fallback 源码：`python Tests/Endgame/run-icon-contract.py --mono ... --csc ... [--framework-dir ...]`，覆盖缺图、未知物品、有限查找和重复诊断。

未验证：完整 Unity 实机渲染、可选补丁包对相同路径的进一步覆盖。尝试读取另一个资源清单中的 `item_icons.json` 时返回 HTTP 403，未绕过访问限制；这里的存在性与图案审阅来自已成功取得的包内真实图像，不依赖该表。
