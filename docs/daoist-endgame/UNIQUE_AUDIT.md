# 仙遗装备：覆盖与实际结算

## 可复现覆盖

`python3 docs/daoist-endgame/catalog/generate.py --check` 从已入库的初始化 SQL 重新枚举并与恢复的 `catalog/eligible.csv` 逐列核对，不执行数据库迁移。详细来源、校验计数与散列见同目录 README 和 coverage.json。

原数据没有字面意义的 `can_dye` 字段；`ov_arm.no_type_drop=0` 是类型掉落资格，不应误称为染色开关。本玩法按已确认的广覆盖口径，为所有 1,619 个已加载且符合此标记的装备基础 ID 制作仙遗形态，没有按名字删掉“测试”等条目。

- 885 个基础能由原有类型掉落分类识别；普通世界掉落仅在这些已生成的装备上追加 1% 仙遗判定。
- 734 个无法由原分类解析的基础保留转换入口，原世界掉落范围不扩张。
- 仅 298 个基础可使用旧随机词条池；仙遗的固定属性和特性不依赖旧词条池，因此其余装备不被漏掉。
- 战士 249、剑客 290、刺客 269、药师 237、术士 237、双法系 12、五职业共用 323、不限职业 2。
- 性别不限 1,421、男性 99、女性 99。

新目录以逐件显式 authored 记录为来源，完整编译必须覆盖1,619个基础。每行保留基础身份、门槛、性别、职业、原始槽位和源 SQL 行。每件单独记录物件身份、来历、用途与取舍，允许1–6属性和0–3特性；不再用词根排列、重复叙事或属性包唯一性作为完成证据。编译检查仅证明完整性与结构有效，不能替代编辑审读和战斗比较。当前1,619行已完整编译并通过字节一致性检查：1,082偏门、486专精、51追逐；1,195件无特性、403件单特性、21件双特性，覆盖29种执行特性。源内容另经逐件编辑及技能适用性审读；这不等于全装备实战平衡认证。

## 实例与执行边界

`Stack.Endgame` 保存 UniqueID（等于原基础 ID 的独立命名空间）、UniqueRollBP（8,000–12,000）与版本。升真仅改变这些字段；原 UID、模板、外观、门槛、绑定、锁定、耐久、精炼、洗炼、融合和镶嵌卡 UID 均保留。

- `domain.Compute` 把该件仙遗的有效属性加入原属性计算流程。
- `scene.passiveStatAffixes` 只追加一次宿阵属性，使用原职业/装备有效性规则。
- `scene.status.resolveStrikeStatuses` 在实际扣血边界应用输出和减伤；条件读取命中前的生命值。
- `scene.skill.onUseSkill` 在法力检查及扣除前修改本次施法的法力、吟唱、范围和陷阱半径，静态技能表不被修改。
- `scene.skill.applySkill` 在实际恢复生命前处理治疗特性。
- 暴击、元素、范围、陷阱和隐身起手上下文随本次攻击传递。隐身起手在原生破隐之前记录，不能因起手后现形而丢失特性。
- 击杀恢复仅在对怪物的正数致命命中结算一次，后续死亡处理与反伤不会重复触发。

29种可执行特性支持逐件选择，其中 skill_economy 支持物理技能节蓝。可选SkillID把施法/命中/治疗特性限定到经原表核实的具体技能；未知ID、错误技能名和职业冲突均被拒绝。同名特性取已激活的最高强度；不同特性按通道相加，上限分别为伤害/治疗 +100%、减伤 45%、法力/吟唱/范围 50%、击杀恢复 8%。所有上限在服务器执行，说明文本也来自同一份特性定义。

## 原槽位兼容

装备源表实际含 14–25 号槽。原 `EquipSet.Set` 与穿脱入口能接受这些编号，但 `Each` 只遍历至 13，导致属性、快照和持久化遗漏。遍历上限已扩到 25；没有重编号、改变原生包字段顺序或扩大旧换装栏。额外部位的客户端操作由新演劫界面承载。

## 事务期间的耐久

`durability.go` 在 TradeBusy 期间冻结玩家装备快照，把服务器已发生的攻击、受击、死亡和技能额外耐久消耗加入已有延后队列。每条记录绑定原槽位、基础 ID、装备 UID 和当时的有效损耗；成功、回滚、权威恢复或回执重放后只处理一次，替换到同槽的其他装备不会被扣旧账。队列先于延后离线的最终存档执行。生产装备必须有实例 UID，无法识别的零 UID 内存夹具不重放。

## 检查入口

`server/internal/domain/unique_*_test.go` 覆盖全部1,619行以及29种执行特性、实例保留、职业/损坏门槛、叠加边界和全部高位槽。

`server/internal/game/scene/unique_effects_test.go` 逐种测试实际伤害/治疗/技能准入/范围目标/生成陷阱/击杀边界，并测试原生高位槽穿脱、快照及金色名称。

`server/internal/game/scene/durability_transaction_test.go` 覆盖等待隔离、成功/失败/恢复/重放、槽位替换、损坏消失、原始损耗及离线最终存档。

上述测试不代表 Unity 实机运行、真实玩家数据库迁移或线上部署。

## 目录重写与历史实例

本次不改技能树。硬点上限20与装备软等级仅保留不生效的定义，不进入当前属性或tooltip。基础ID、物品UID、保存的UniqueRollBP、黄色词条、镶孔与卡片快照均不重写；名称和固定仙遗加成按当前权威目录重新派生。负面属性的灵性缩放按收益方向处理，避免“升真”反而加重诅咒。

新掉落仙遗和黄装转换必须分开比较：前者可能没有自然词条，后者保留全部原词条。强物理/法术专精需要相对同等级同基础黄装有实际优势，偏门多数通过用途集中与机会成本体现，而非统一微弱词条。统计去重不能证明这条要求。

宿阵在相同通道胜出后，同时获得固定属性和条件/具体技能特性；被抑制的阵不提供阵特性，独立星篆效果保留。40阵源见 `server/docs/endgame/astral_runes.json`；每阵有独立背景、用途和取舍。叠加上限与同名最高规则和仙遗共用，不能靠多件同名特性形成递归触发。
