# 五职业原始技能审计结论

审计日期：2026-10-12。范围：原五职业全部技能的来源、资产差异及实际执行影响。这里只生成证据与字段裁决，没有修改业务源码、数据库或资源。

## 结果

- 旧备份包含149个战斗技能，当前资源146个；对应SQL还有生活技能11005，故SQL是150个ID/750行，战斗部分149个ID/745行。
- 独立重算得到 **68个修改、3个删除**。战士15、剑客13、刺客10、药师18（另删3）、术士12。
- 71项全部给出字段级判断：`restoration-decisions.json`（472个字段/阶级判断）、`restoration-decisions.md`。精确旧值、现值和SQL交叉值在 `verified-asset-differences.json`；易读清单在 `verified-asset-change-ledger.md`。
- 旧备份149项的1–5阶说明，共745条，与SQL逐字一致，零差异。这是恢复原分级说明的重要交叉证据；不能因此认证旧备份或SQL所有数值都是腾讯官版。
- 当前资源修改8个名称、25个顶部说明、35个分级说明、12组等级门槛、15组吟唱、15组冷却、2组法力、3组前置、19组目标/范围字段。57个技能至少一个等级字段变化。

## 已证实应恢复的核心内容

1. 恢复原职业身份及被动作用范围：破魔→枪势、维护→破军、风斩→剑意、解除陷阱→拆解、陷阱回避→布雷、净化术→净世、祝福术→祝祷、鹰眼→照亮，这八个现名伴有机制改写。旧名有SQL及独立职业资料支持。
2. 撤除已证实的自定义叠层、全状态抗性扩展、额外减伤、额外增伤、固定治疗改百分比治疗等原技能改写。例：风斩只增强真空；饮血五级吸血28%而非44%；火/山诀保留攻防交换；陨星即死概率固定2%而非升到6%。逐项数值在清单内。
3. 单体改群攻确证有10102罡气、10122混沌、10317圣光。前两项阶段修正已有源码防护；圣光仍需恢复实体单目标。术士陨石、绝对零度本次没有形状修改，不能把它们误报为群攻改写。
4. 恢复被删除的10316清身术、10318解咒术、10321防御术元数据。现资源把前两项部分功能合进净世，把防御并入祝祷。SQL与历史资料都保留独立技能。
5. 恢复有旧备份及SQL一致支持的等级门槛、吟唱与冷却参数；客户端必须消费同一权威等级值。对本来就与SQL冲突的备份扁平值，裁决为同步服务端契约并保留历史出处不确定性，不能照旧文件直接复制。

## 明确不可机械回滚

- 野战半径250→150：现150同时有SQL与旧资料支持。
- 雷霆之怒shape2/r150→shape0/r0：次普攻增伤是自身状态，旧几何误导，保留当前修复。
- 神圣庇护、加速、瞬击：原本就是友方群体；旧备份shape0是缺失，不能恢复成单体。天罚原本也是群体，shape2/dist450有SQL支持；半径150/200另行待裁决。
- 四个陷阱shape0→2/r100：这是符合原陷阱爆发范围的投放/预览元数据，不等于擅改成直接群攻。
- 阴影跳跃canFriendly0→1：旧说明本来允许队友，保留修复。
- 震慑旧顶部恐惧/未生效文字不能恢复。2005-12-22正式更新镜像明确改成半径150群晕。煞气、必中背刺/暗杀、45级冻气同理保留正式更新。
- 10212旧备份与当前都叫偷窃术，旧备份顶部是偷窃、1–5阶却误接纯伤害。当前偷窃方向有独立同期实玩证据。不能恢复损坏的旧分级文字，更不能把SQL游龙掌自动认证为原名。精确经济规则仍未闭合。

## 仍待核实的原版数值

- 旧备份本身并非官方签名发布：1.0/build0、ad-hoc签名，没有可认证的腾讯发布校验值。
- 旧备份所有745分级描述匹配SQL，但几乎所有高阶MP重复一级MP；本地再次直接核对完整JSON证明不是导出器回填。不能覆盖SQL逐级MP。16项还携带不可学习的6–10阶块，而maxlv保持5。
- 备份顶部与分级文本有矛盾：火/山诀顶部15秒、分级30秒；冰箭顶部165%、分级100%起；偷窃顶部偷物、分级普通伤害。优先保留逐项来源，不选一份文件全盘当权威。
- 战吼/挑衅、天罚、鹰眼、多重投掷、时之封印等仍有描述半径与数值字段矛盾。除正式更新明确的煞气150，不能凭“更早”批量改服务器半径。
- 祝福/光盾/衰弱的旧pre=10321，当前pre=0，而SQL本来为0。历史文本没有前置关系；这三项暂缓。加速、燃烧强化也有既有资源/SQL前置差异。
- 独立静态职业页属于混合年代，含未实装恐惧、60级冻气等已被正式更新替换的记录。不能用整页覆盖现有技能。

## 已证实的执行影响

- 名字、旧卡片、热键标签、图标和学习UI读外部SkInfo；V5服务器说明不覆盖所有身份字段。
- 目标shape/description决定实体/地面/方向施法，真实影响请求路由。距离还决定自动接近停止点；罡气备份100也比服务器75远，阶段修正不能回退。
- 客户端LocalNotEnoughMp在发请求前读取资源MP。净世现100但服务端原值48/52/56/60/64，祝祷现120但服务端35/37/39/41/43，能阻断本应有效的施法。
- 三个缺失条目不是简单“全隐藏”。如果布局保留且V5返回等级，图标位/等级/升级按钮可能仍出现；但缺少hover、拾取、技能名和图标。已保存快捷键可能继续发请求，却回退Instant/target0，丢失友方选目标语义。后续布局补充已证实旧/现layout都保留三个节点，缺的是技能元数据而非节点。
- 多数新增叠层/伤害描述没有当前服务端对应效果；这里确证的是客户端定义被改写，不能把它们全说成当前服务器实际打出的效果。
- 独立ReferenceSkillEffectCatalog没有查到生产调用者，不能把它误报为第二条已证实可达施法执行链。

## 服务端原始功能缺口也未完成

现有导入说明要求但加载定义没有对应实现的项：破防减防、罡气击退、幻影降命中、金缚定身、封法禁技能、混沌禁增益、进阶背刺击晕、击晕控制、狙击定身、驱魔种族限制、天罚随机负面、圣光致盲、神威定身。另烟雾状态补全额外加入描述没有的魔防下降；山字诀状态缺攻击代价、仙风云体状态缺移动限制、枷锁术状态缺攻速降低。现有11项参数完整可实施、7项有明确缺证，见 `runtime-restoration-gaps.json`。详细状态映射与未知概率在 `five-profession-known-issues.json`。

已给定明确时长/数值者可按原说明另做实现；缺失的神威概率、天罚状态池、圣光致盲参数、击退距离等仍不能猜。原有净化概率、鹰眼时长、击退距离、耐久减免等有作者补定记录；这些不是已认证官版数值。
