# Equipment, rune and cube requirements audit

Date: 2026-10-13. Requested baselines: server `cd43b8f`, client `fa41a5b`.

## Bottom line

The listed content/mechanics/presentation requirements are supported by inspected production code, data and focused executable contracts. **Current-wild-drop scope is independently closed against the assigned fully migrated test database: exactly259 reachable/dyeable/non-ascended <=60 bases, exactly259 current uniques, zero missing and zero extras.** This is still not a real-client/deployment completion certificate: no actual Unity rendering or deployed-server session was exercised.

No source files were changed by this audit. Other workers were concurrently editing NPC/rift-related files. Client UI contracts were therefore repeated against an isolated `git archive fa41a5b` under `/tmp/equipment-client-fa41a5b` and passed. Server focused tests used the shared checkout while the relevant equipment implementation remained at the inspected baseline; this is not a final integrated check of those workers' changes.

## Actionable findings and boundaries

1. **Reachability resolved with the real runtime edge:** an initial seed-only/direct-spawn trace proved249 bases and left ten tier-6 bodies unresolved. The actual migrated database plus `internal/game/spawn/spawn.go:113–151` closes all ten through dynamic elite respawn: 虚空之境(map84) → 月光兽3038 → EliteID4148 魔性的月光兽 → positive tier-6 clothing row. The ten are 2829/2830 冥法服（男/女）, 2893/2894 龙吟铠（男/女）, 2895/2896 青龙铠（男/女）, 2899/2900 圣贤服（男/女）, 2901/2902 朱雀铠（男/女）. The final read-only SQL matches actual loader validity gates (positive monster level/HP, AI template, known map, non-city/non-dungeon, positive drop chance, ordinary→elite kind requirements), checks real dye pools, and obtains259 paths with no catalog mismatch. **Do not remove these ten.**
2. **Do not mistake broad template eligibility for the approved scope.** Native/dyeable/non-ascended <=60 template screening produces 273 candidates, but the extra 14 are all tier-7 clothes and there are zero positive native type-drop rows covering clothing tier 7 in the parsed seed. They are 9501/9502 刺客男1/女1; 9601/9602 法师男1/女1; 9701/9702 剑客男1/女1; 9801/9802 药师男1/女1; 9901/9902 战士男1/女1; 29833/29834 幻想女神/男神（飞前）; 29847/29848 万人迷/国民小生（飞前）. These 14 are **not** a demonstrated omission from the current catalog.
3. **Missing end-to-end visual evidence:** color/order/composition/native buff columns and icon lookup pass production-method contracts, but those use Unity/artwork substitutes. No current packed-resource visual census or real Unity screen was opened here. Thus the audit proves code behavior, not that the installed client presents every icon, font line and panel correctly.
4. **Database backing is implemented and the actual integrated test DB was queried read-only.** Runtime reads normalized database tables and fails closed on missing configuration. Focused loader/configuration tests passed; actualSQL verified the full259 scope in `/tmp/endgame-items59-final-20261013/data` using BEGIN READ ONLY/ROLLBACK. The full PostgreSQL loader test was not rerun; the live deployed database was not inspected.
5. **Nonblocking scope-hardening opportunity:** `ValidateUniqueCatalog` checks equipment existence, `NoTypeDrop`, local base validity and class/level metadata equality, but does not reconstruct reachable wild paths or enforce the previously excluded set. `RollUniqueDrop` consults catalog `NativeDropEligible` plus equipment `NoTypeDrop`, not the whole source graph. Future DB edits could silently widen the seed scope unless an independent database reachability/exclusion test is added. This is a validation gap; no currently generated out-of-scope drop was reproduced.
