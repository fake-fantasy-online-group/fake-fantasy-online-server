# 周天鼎原生房间放置

## 已验证来源与取舍

复用龙城巧匠左慈背后的原生商会房间，不创建替代房屋、地图号或资源。原龙城左慈为 `qw0007 / npc_id 73 / sprite 611 / N611FY / (9441,6195)`；原合成炉 `N903` 及全部原 NPC 均保留。

| 用途 | 原生资源 / 数据 | 核对结果 |
| --- | --- | --- |
| 房屋入口 | `map/qw0007.gsm`，library object 754，`object/DH/DH_FY_1501.gso`，左上角 `(9155,5907)` | 实际门光位于左慈后方商会建筑台阶 |
| 入口交互 | `qw0007 / proc_id 5` | 原有目标 `map 506 / (498,541)`，原 polygon 中心 `(9250,6060)` |
| 室内 | `map/qw0506.gsm`，原 map_defs 506 / 商会 | 900×675 原画；木台、柜台、炉灶、货架、原有出口；原库无室内 NPC |
| 鼎外观 | `avatar/npc/npc90301.gsn` | 已检查真实解码像素：金绿三足火焰鼎；没有重新绘制或修改资源 |
| 未选模型 | `avatar/npc/npc90201.gsn` | 蓝色光焰机械合成炉，与金鼎外观不同 |

模型首帧经过现有生产 `DimgDecoder` 的 Decode / DecodeRaw 像素一致性检查，0 缺帧、0 差异。场景证据为原 cover 与原物件图层合成，不冒充运行中的 Unity 截图。此次新读取 9 条资源，总压缩体积 443,902 字节；qw0506 地图与已有场景物件复用本云任务先前的缓存，没有下载整包。

## 数据库约定

- 专用 NPC：`qw0506 / npc_id 1 / sprite 903 / 周天鼎 / Nzhoutianding / (620,430) / dir 67`
- 位置在原室内右侧木台上，不挡入点或原出口
- 入室：`qw0007 / proc 5 → 506 / (498,541)`
- 出室：`qw0506 / proc 1 → 7 / (9330,6099)`
- 保留原 map_defs 的“商会”名称和原生场景；仅专用 NPC 显示“周天鼎”
- `Nzhoutianding` 由专用业务交互处理，绝不借用或改写原 `N903` 合成服务
- 运行时配置只放在原 `map_npcs`、`map_teleports` 中，无新业务表

## 原出口遗漏的定点修正

init-0 中商会出口最初记录龙城旧坐标 `(8898,6707)`，但同文件后面的 poly UPDATE 以新坐标 `(9330,6099)` 为条件，导致 UPDATE 未命中，出口 poly 留为 NULL。

migration75 仅修正这一对门：旧坐标应用原龙城偏移 `(+432,-608)`；入口 back 坐标同步；室内使用 init-0 原有 polygon `[583,580,630,620,675,591,642,550]`。不扩大门面，也不影响其他地图门。

龙城返回落点在入口菱形触发面之外，避免静止落地即重新入室。室内落点也在出口多边形外。

## 碰撞与验证

原 `.msk` 的生产语义为 10×10 像素格，`0x80` 位表示阻塞。已检查：

- 龙城左慈 `(9441,6195)`、入口中心 `(9250,6060)`、返回点 `(9330,6099)` 全部可行走；四向格路径分别 32、21 步
- 室内入点 `(498,541)`、鼎 `(620,430)`、出口内点 `(630,585)` 全部可行走；入点到鼎、入点到出口的四向格路径分别 24、18 步
- 模型可放置不是只凭坐标范围判断，同时检查了原室内画面与 mask 可达性

`server/tests/sql/validate_zhoutian_placement.py` 在独立、无监听 PostgreSQL 17 临时库加载 init-0 的全部原生 map_defs / map_npcs / map_teleports 行，验证首导、重放、回滚、缺地图/左慈/门链和占位冲突拒绝；通过全量行差集证明原地图、原 NPC、其他门不变，并验证 NPC 重放保留管理员后续放置。结果：`ZHOUTIAN_PLACEMENT_POSTGRES_PASS`。

这是数据与原资源级验证，尚不等同于真实 Unity 场景中的完整点选、对话及容器 UI 验收。
