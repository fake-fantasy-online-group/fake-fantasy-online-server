# 装备等级与协同（migration74）

本轮依据新要求修改新增协同规则，取代旧 V5 文档中“装备等级不参与新增协同”的约束。原始技能自身效果、成长曲线、58 条原生被动关系、学习等级和硬点前置保持不变。

## 已实现的规则

- 原有 70 条新增协同边从 `hard` 改为 `effective_training`，来源读同一份未经过协同修饰的实际有效等级：硬点 + 生效装备等级 + 既有显式授予规则允许的等级。
- 全技能、职业、左系、右系、辅助系、学派、指定技能加级复用原装备等级解析。未学技能仅有普通装备加级仍为零；装备不能满足硬点学习前置。原生被动继续读 `effective_raw`。
- 系数取决于受益技能的原始学习等级，不根据技能 ID 或当前加点等级猜测，不递归计算。

| 受益技能学习等级 | 每来源有效等级加成 |
| --- | --- |
| 1–29（当前目录实际为 10、15、20、25） | 3% |
| 30–49（实际为 30、36、43、45） | 4% |
| 50–69（实际为 51、60） | 5% |
| 70–100（实际为 70、80） | 6% |

所有新增百分比效果采用上述系数；两条原固定治疗 +2 边改为治疗效果百分比。原有协同关系和每目标最多三个不同来源不变。减耗的 80% 限制、控制时长等既有语义限制仍保留；原本收费技能叠加协同和装备减耗后至少消耗 1 MP，原本免费技能仍免费。6% 是每级系数上限，不是总贡献上限。

## 数据与运行路径

迁移从 `gamedata.ov_skilldesc` 第一等级的 `level_need` 计算系数并持久化至 `game_skill_synergies`；运行时只消费类型化配置。数据加载拒绝新模式中小于 300 或大于 600 BP 的系数，拒绝把固定治疗伪装成百分比。旧 `hard` 模式仍用于保留已经单独调整过的管理员配置和历史回归。

迁移只更新精确匹配旧审阅边的配置；原有管理员系数、模式、效果修改不被覆盖。`game_skill_synergy_update_history` 保存迁移前的配置及更新数量；重放不会覆盖后续管理员修改或恢复已删除的边。干净基线更新 70 条，保留 58 条原生关系。

施法、服务端面板与持续效果均使用相同的 raw snapshot。换装、损坏和卸装使新施法按现有装备重算；持续效果使用施法时与当前来源等级的较小值，后穿更强装备不会强化旧施法。协同输出从不回灌技能等级。

贡献乘法以 int64 计算，DTO 新增可选 `sourceEffectiveRank` 十进制字符串，并将 `contributionValue` 扩为 int64；`investedHardPoints` 继续只表示投入，`equipmentApplies` 表示该条是否读装备有效等级。既有 EngineRank 的显式数值边界不变，超界不会静默变成20级。极高最终伤害/范围等仍采用引擎现有整数表示的饱和处理。治疗分数采用约分后的精确有理数，避免高等级乘法溢出变负。

发布时需同时更新客户端和服务端，并先执行迁移74。新客户端能读取旧 DTO；旧客户端的严格硬点校验不能理解装备来源等级，不应与本次新服务端混用。没有新增 opcode 或帧格式。
