# 全149技能等级收益审计 v6

## 结论与边界

149个技能在20→21、21→22、30→31、50→51、100→101这五个逐级比较点，均存在至少一个实际数值载荷变化。主动输出技能保持原伤害/治疗通道，功能主动增加使用效率，封顶被动沿原目标接续收益。这是修复后native-restored fixture、domain曲线及status resolver的执行验证，不是每个技能均完成真实对局、动画或原版全部附加机制验收。

7个原版附加机制仍有证据/实现缺口，逐行明确列出，不能因主伤害或其他轴成长而标成全机制完成。10212的伤害成长与偷窃合同禁用并存。

审计测试：`server/internal/game/scene/skill_growth_audit_v6_test.go::TestSkillGrowthAuditAll149NativeFixtures`。使用 `nativeRestoredSceneFixtures(t)`，加载745原始技能行与恢复层55行、状态恢复层，然后通过真实 `SkillTable.Get` 和 `StatusTable.ResolveSkillApplication` 求值。裸Level、ProgressionRanks、FirstLevel、状态ID等元数据不计收益。伤害/治疗分数规范化为有理数，控制pressure转换为所有1..90抵抗值的实际整数判定。法力/冷却/吟唱成本只有下降才计收益。

复现：在server目录加载测试环境后，设置 `SKILL_GROWTH_AUDIT_PATH=/tmp/skill-growth-audit.json`，运行 `go test ./internal/game/scene -run TestSkillGrowthAuditAll149NativeFixtures -count=1 -v`。JSON包含全部字段变化，表中仅选择每次转换的一条代表性证据。

## 数值轴与封顶解释

- 原成长轴比较原1→5数值，含原消耗等成本变化，用来说明来源，不把成本上涨当收益。
- 饱和阈值列在逐级6..200扫描中最后一次变化的等级，之后到200保持不变。这不是全int32区间终局证明。已经在5级满值、固定常量、或5级后一直恒定的轴，参见[状态专项审计](skill-growth-review-v6-status.md)和被动曲线代码。
- 主伤害百分比、原有回血/护盾/周期伤害等沿既有通道增长，不追加AOE或目标，不加无关固定伤害填充。
- 功能主动蓝耗为五级基础值 × 50 / (50 + rank−5)，运行时用分数结算；平均值严格下降，但单次整数扣蓝不保证相邻等级每次都不同。
- ManaEfficiencyRanks为原指定技能的耗蓝效率；ProgressionOverflow按原被动类型映射指定技能效率或相应防护通道；ProgressionRestoreMP为抵抗成功后的法力恢复。这些新增被动载荷必须由各自runtime消费测试佐证，不能仅因字段变大就视为每次触发都有收益。
- 原控制命中pressure受整数概率精度限制，pressure1781起所有0..90数值抵抗已为0；纯计数器继续变化不算收益。不可穿透真正免疫。
