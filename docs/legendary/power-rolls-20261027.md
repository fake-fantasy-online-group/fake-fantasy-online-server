# 威能数值范围与兼容性

## 数值契约

- 330 个威能逐项分类：315 个具有实际可浮动的收益参数，15 个仅为完整机制开关，保留固定机制。逐项参数和运行调用点见 `power-roll-coverage-20261027.json`。
- 一个实例保存一个不可变 `PowerRollBP`，新数值范围为现有收益基准的 75% 至 100%。参数采用各自明确单位，整数取整至少为 1。多参数使用同一个抽签结果，不拼接不同掉落的最大值。
- 不把学习要求、触发门槛、目标数量、必定命中/暴击、免费施法或免疫等机制统一乘系数。每个威能至少选取一个有意义的可变收益，其余明确固定部分不变。
- 减伤、耗蓝和冷却降低只调整“降低的比例”，不乘完整伤害或最终冷却。低品质不会反而变强，也不会把概率或计数误改成 0。
- 原有 `PowerRollBP=0` 装备继续使用原有满强度，存档读取不会重掷。新生成/刻印装备展示实际参数及该参数范围，继续使用正常的“威能名：效果”一行。
- 同名威能不叠加，选择实际 roll 最强者，相等时使用稳定 UID 顺序。翅膀提取保留捐赠暗金的实际 roll，升阶和转换保留现有插槽实例。
- 施法接受快照保存 roll，施法后装备改变不会追溯升级飞行中的攻击。永久准备状态的来源快照和装备签名包含 roll，同 UID 重刻后能重新构建。

## 代际与持久化

- 掉落规则 5 / 大秘境规则 17 才开启新数值抽签。旧规则快照不增加随机调用，也不改变旧奖励结果；原装备/已生成奖励不重掷。
- 新世界掉落、首领额外奖励、新大秘境奖励与新唤醒入口使用有范围实例。旧代际回放使用显式旧接口。
- `PowerRollBP` 使用现有暗金/翅膀 JSON 存储；迁移 115 只增加新冻结规则版本和激活选择，不改玩家现有装备。

## 验证边界

- 元数据加载验证威能 ID、原描述片段、正数参数、重复描述片段和明确固定原因。
- 所有参数逐个覆盖 7500 至 10000 的单调性和端点，检查非法 roll、旧值、JSON 往返、同名最强选择、翅膀保留。
- AST 审计验证字面量调用的 key/base 与所属威能元数据一致，并检查共享工厂调用点存在；它不能替代条件路径运行测试。
- 专项运行测试覆盖法术、近战、通用技能、减伤、护盾、法力、冷却、概率、移动、持续时间、子攻击快照和描述一致性；旧职业回归同时保留。
- 全包及真实 PostgreSQL 验证结果由最终集成检查单记录，不能把专项通过描述为全包通过。
