# 威能录与数值范围（2026-10-27）

## 玩家规则

- 威能录按角色保存。周天鼎实际分解暗金时，收录该装备的威能；预览、失败、取出材料不收录。
- 相同威能只保留一个最高的整体数值档位，低值和重复分解不会覆盖高值。多参数使用同一个装备档位，不拼接来自不同装备的单项最大值。
- 已收录威能可重复刻印到背包中的暗金装备。无新增货币或材料消耗。替换威能及其档位，保留装备 UID、底材、品质、六条属性、强化、绑定及来源等级。
- 装备必须解锁，并符合该威能既有部位、职业及来源等级要求。职业威能继续支持所有实际装备部位；通用威能保留既有类别部位规则。玩家等级不能绕过装备来源等级要求。
- 只能刻印当前职业或全职业威能。可以查看已收录的其他职业记录，但不能借此给当前职业激活其他职业能力。
- 同威能已有装备比记录更强或相等时不进行无效/降级覆盖。换为另一种威能可以正常覆盖。
- 收录值提升不会追溯改变之前刻印的装备；需要重新刻印。
- 无独立数值的机制型威能正常收录和刻印，不杜撰强度数值。
- 未变动的旧装备保留既有固定数值（旧字段缺省为最高档位）；新刻印数值型威能显式保存最高或实际档位。

## 实现边界

- 不增加原生 opcode；沿用 endgame.v1 JSON 扩展，新增 powerbook.list / powerbook.imprint。
- hello 的 result.powerBook=1 标记客户端入口可用。未支持该功能的服务端不显示入口。
- 记录位于 character_endgame_state.payload.powerBook；装备档位位于 equipment_legendary_state 的现有 JSON。收录和装备档位本身不新增表。数值生成策略通过迁移 115 增加独立开关并发布 Loot 5 / Rift 17，旧 Loot 1–4、Rift 1–16 和已生成奖励保持原随机序列。
- 分解物品、收录记录、版本号及请求回执处于同一个既有 EndgameBackend 原子事务。存储失败不提前改内存；提交应答丢失通过回执和权威快照恢复。
- 刻印走同一请求回执、版本 CAS 和物品事务锁。客户端不能提交威能数值。
- 翻页按 powerId 排序，每页不超过 50 条，并检查实际 JSON 字节预算。nextCursor 为已发送累计条数。客户端遇到跨页 revision 变化需重刷。
- 只记录实际分解，翅膀提取不是分解；不扫描/倒推部署前已经销毁且没有记录的装备。

## 协议共享夹具

server/internal/game/scene/testdata/powerbook/ 包含由实际场景处理器生成的 list、imprint-request、imprint-success、imprint-error JSON；Go 场景测试与客户端测试共同消费，防止端间 DTO 漂移。

## 验证

- Domain：最高档位比较、旧值兼容、记录读写、无关角色进度保留、损坏数据拒绝、刻印不改其他装备事实、职业/部位/来源等级限制。
- Scene：真实周天鼎分解原子候选、提交失败不耗物不收录、刻印回执重放、旧版本拒绝、330 条记录分页和传输预算。
- Store：state / snapshot / receipt 三个失败点回滚；COMMIT ACK 丢失恢复；多次重放不重复；重登持久化；不同角色隔离。
- Protocol：闭合字段集、重复字段及大小写别名拒绝、63 位 UID 无精度损失、拒绝客户端伪造 rollBp。
- 原生客户端操作和真实 PostgreSQL 集成需分别按运行环境披露，不以云端模拟测试代替。
