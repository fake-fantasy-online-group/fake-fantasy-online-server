# Rift elite rules v6 (staged)

Migration 80 publishes an immutable v6 rule row but does not change the active pointer. Existing and new live admissions remain v5 until a separately approved activation; no client-visible mechanics are enabled by this migration alone. V1–v5 keep their exact frozen rule snapshots and three legacy abilities. No native binary protocol layout changes. Migration 81 performs the paired client/server release activation from v5 to v6; see [the activation gate and SQL validation](elite-activation-postgres-audit.md).

The complete tunable config is `elite-skills-v6.json`; the SQL JSON literal is verified against it by tests. Stable IDs: 0 golden_body, 1 clones, 2 death_lava, 3 lightning_orb, 4 ice_orb, 5 agility, 6 poison_pool, 7 walls. Trigger types are active, death, passive. Eight approved guardians and their three new affixes are explicit config rows. Guardian rows reject death affixes in this initial release: completion/reward timing therefore stays unchanged.

## Mechanics

- Each active ability has its own successful-cast cooldown, with 3–6 second first-cast grace and one-second retry for failed admission. Native accepted casts finish first. A short 650 ms recovery gates actions; persistent effects never lock native AI for their lifetime.
- Golden body uses ordinary status buckets: 5 seconds, 95% physical/magic mitigation with explicit 95% cap, new harmful status block and suppression of old harmful status effects. Agility is a permanent +100% movement bucket based on unbuffed scaled stats.
- Clones inherit the current ordinary monster definition including native skills, AI and immunities. Independent native skill/status runtime, 10% scaled base HP, full scaled base offense/defense, three per owner, 20 seconds. Capacity and all placements are validated before replacing an old group. Summoner ownership excludes native rewards/respawn; no rift progress registration or elite affixes. Owner death/clone expiry removes descendants without death effects.
- Lava captures real-death offense and is queued with event-time deaths through economic reconciliation. One death creates one three-second explosion independent of corpse removal and guardian-arrival clearing. A delayed economic admission starts a fresh visible warning; it does not replay hidden elapsed attacks.
- Lightning has five 30% rings at +1/+3/+5/+7/+9 seconds. A ring expands for one second to radius 220 with width 40; per-ring hit deduplication is independent. Missed complete rings are not replayed after a scene stall.
- Ice explodes at three seconds for 140%, then attempts a two-second native freeze through ordinary chance, resistance, immunity and overlay rules.
- Poison has a 20-second lifetime. First damage is after one continuous second; 5% rising one point per second to 15%. A normal 20-second stay totals 245%. Per-pool/per-target occupancy resets on exit, death or disconnect. Overlapping pools share one per-target one-second damage cadence, including staggered casts. The winner is the highest target-aware nominal damage after native defense, elemental/status mitigation and a cloned shield preview; comparison never consumes combat RNG, real shields, HP or status effects. Only the winning source enters the ordinary random strike pipeline. Stable instance ID breaks ties. Missed ticks do not burst on recovery; the exact 20-second final tick resolves before removal.
- Walls are three disconnected oriented segments, physical length 80/full width 20, gap at least 80, 15 seconds. A complete safe group is required. Movement/push/AI paths collide with geometry expanded by 12 on both local axes. Fresh placements use an extra 40 clearance. Static LOS/projectiles stay unchanged.
- Active persistent hazard budget is 6, separately from four same-frame cast admissions and up to 32 reserved real-death orbs. The budget is checked against the unchanged 60 KiB wire envelope; excessive configurations fail validation rather than truncate gameplay snapshots.

## JSON extension

V6 rift snapshots add `mapId`, `serverNowMS`, optional `hazards`, and per-aura optional `abilityIds`. All timing fields in one snapshot use a single sampled server clock. An empty omitted hazards array is a full empty snapshot, not a delta. V5 leaves all additions absent.

Each hazard has `id`, `sourceId` (native uint32 decimal string), `abilityId`, `mechanism`, `x`, `y`, `radius`, `bornMS`, `expiresMS`, `remainingMS`; optional `width`, relative `firstPulseMS`, `pulseMS`, `propagationMS`, and `walls`. Remaining time equals expiresMS minus serverNowMS. Hazard identity is run/floor/monotonic effect sequence. Walls carry `id`, `x`,`y`,`x2`,`y2`,`width`, with exact finite floating-point centerline endpoints and flat ends, sharing their parent's deadline. Physical walls use exclusive expiry. Maximum wall absolute coordinate is 1e7, width 1024, length 2048; authored defaults are smaller.

`elite-wire-v6.json` is generated by the production Go riftView in `TestRiftEliteWireFixture`, not manually written. Set `RIFT_ELITE_WIRE_FIXTURE` to regenerate. Server sends the full current snapshot before arming newly connected/revived players for a hazard, with a one-second grace. No old pulse or poison occupancy is transferred to a new connection.

## Persistence and boundaries

Effect identities, immutable attack snapshots, clocks, occupancy, pulse receipts, per-skill cooldowns, clone ownership/expiry, and wall geometry are in the run aggregate. Economic pending freezes gameplay; queued real-death offense survives aggregate replacement. Wall recovery is deterministic and atomic per owner; an unsafe group is removed together with its visual hazard. Floor retirement and terminal cleanup remove all temporary state; guardian arrival removes monsters while preserving existing hazard lifetimes.

Ordinary network reconnect retains the same actor, native monsters/clones and effects. Whole-server restart continues the existing interrupted-run compensation policy; this change does not introduce a new active-run monster/AI resurrection protocol. A reconstructed actor invalidates old transport viewer identities and never replays unseen hazard history.

### Authoritative visual receipts

V6 auras additionally expose optional `goldenUntilMS` only while golden body is actually active, and `cloneOf` for temporary clone entities (class 0, no affixes). `impacts[]` is a short-lived, server-confirmed receipt list: each receipt has the originating hazard `id`, `mechanism` (`death_lava` or `ice_orb`), `x`, `y`, `radius`, `atMS`, and `expiresMS=atMS+700`. It is sent only to connection generations which saw that hazard; removal or local expiry alone never implies detonation. Clients select a frame from the received authoritative clock and never replay to a late joiner. These are presentation receipts, not collision objects or combat timers.

V6 `rift.context` also binds `runId`, `floorIndex`, `mapId`, and `serverNowMS` within its existing string result map. This prevents a delayed snapshot for a previous floor on the same native map from rebinding wall prediction after a context transition.
